# Wiki Schema

## Domain

Google Cloud **Professional Cloud Architect (PCA)** exam preparation, built from
the 16-video "CertPro Deep Dive" question bank that has already been extracted
into `exam/exam.db` (340 question slides, Q1-339).

This wiki exists to answer two questions fast:

1. **"What does the exam mean by Dataflow?"** — a concept page carrying the
   teaching, the traps, and every question that exercises it.
2. **"Which questions test this concept?"** — so a practice exam can pull the
   explanations from questions that mention it.

## Where the truth lives (read this before editing)

| layer | source | trust |
|---|---|---|
| `exam/exam.db` | slide OCR + green-pixel answer detection | **source of record** |
| `wiki/raw/corpus/` | export of the DB, hash-pinned | immutable, regenerable |
| `wiki/entities/`, `wiki/concepts/` | agent-written markdown | derived, editable |

Two hard rules learned from measuring this corpus:

* **Concept linkage comes from the WRITTEN slide text** (question stem + option
  lines), never from the transcript. The presenter often never names the concept
  while explaining — `Dataflow` is printed on 17 slides but spoken in only 4 — so
  a transcript-driven index would miss ~77% of mentions.
* **The transcript is teaching prose, not terminology.** It is autogenerated
  speech-to-text and it mangles names: `IAM` -> "IM", `microservice` -> "micros
  service", `Cloud Run` -> "DCloud Run", `Dataflow` -> "Dataf Flow", `Kubernetes`
  -> "Kubernet". Any sentence quoted from it MUST be flagged inline as
  `[ASR]` so a wrong product name is never mistaken for the exam's own wording.

## Conventions

- File names: lowercase, hyphens, no spaces (`cloud-load-balancing.md`)
- Every page starts with YAML frontmatter (below)
- Use `[[wikilinks]]` between pages; minimum 2 outbound links per page
- Bump the `updated` date whenever you change a page
- Add every new page to `index.md` in the right section, alphabetically
- Append every action to `log.md`
- Quote the exam's own words in `> ` blockquotes; quote ASR as
  `> [ASR] ...` so the two are never confused
- Never invent a GCP fact that is not either in the corpus or in Google's own
  docs. A page may be thin; it may not be wrong.

## Frontmatter

```yaml
---
title: Dataflow
created: YYYY-MM-DD
updated: YYYY-MM-DD
type: entity | concept | comparison | query
tags: [from taxonomy below]
sources: [raw/corpus/questions.md]
questions: [6, 19, 23]        # question numbers this page is built from
confidence: high | medium | low
contested: true                # only when the corpus disagrees with itself
---
```

`confidence` reflects how well the corpus supports the page:

- `high` — the concept is printed in several questions and the answer is green-verified
- `medium` — mentioned in 1-2 questions, or the teaching sentence is ASR-derived only
- `low` — a single mention, or the corpus contains no teaching for it

## Tag Taxonomy

- Domain: `compute`, `storage`, `database`, `data`, `ai`, `network`, `security`,
  `ops`, `devops`, `hybrid`, `cost`
- Kind: `service`, `feature`, `trap`, `exam-topic`
- Meta: `high-frequency`, `contested`, `thin`

Every tag on a page must appear above. Add a new tag here first.

## Page Thresholds

- **Create a page** for a service/feature that appears in 1+ questions (this bank
  is small enough that even single mentions are worth a page, because a single
  mention is still a thing the exam can ask)
- **Trap pages** are created by hand from patterns visible across questions, not
  per question — one page per reusable trap ("the most-managed option", "the cost
  trap", ...)
- **Split** a page over ~200 lines into sub-topics
- Case-study material (Mountkirk, Cymbal, EHR, Altostrat, HRL, Dress4Win) is
  deliberately NOT its own page set — the user scoped the wiki to products and
  traps. Case-study context stays in the question rows.

## Entity Pages (GCP services and features)

Generated from `exam/exam.db`, one per concept, and meant to be edited by hand
afterwards. Required sections:

1. **What it is** — one or two sentences, from the corpus or Google's docs
2. **Questions that test it** — table of question number, what the slide says,
   link to the watch URL
3. **Teaching** — `[ASR]`-flagged transcript sentences that mention the concept
4. **Traps** — for each wrong option seen, the reason the transcript gives
5. **Links** — `[[related-concept]]` wikilinks

## Concept Pages (trap patterns)

Hand-written. Required sections: the trap, how it looks in the exam, real
examples (`Q47`, `Q51`), and how to avoid it.

## Update Policy

1. Regenerate `raw/corpus/` from the DB when the DB changes (check the sha256)
2. If a regenerated raw file differs, note it in `log.md` and re-check any page
   whose `questions:` list is affected
3. If the corpus and a page disagree, trust the corpus and mark the page
   `contested: true` with both positions dated
4. Never edit `raw/` by hand
